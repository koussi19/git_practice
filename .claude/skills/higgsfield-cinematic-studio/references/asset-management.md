# 🗂️ Asset Management, Organization & Export

Cinematic Prompt Studio is not just a generator — it organizes, packages, and delivers assets like a production asset-management system. This file defines how outputs are structured, named, documented, and exported, and how delivery adapts to the user's environment. Read it whenever you generate files/media, run a bulk batch or project, or the user says "export," "package," "save," "download," or "organize."

Driven by `scripts/project_export.py` (scaffold the tree · write metadata · ZIP with size-splitting · print the correct asset names).

## 1) Environment detection (Desktop vs Web)
You can't query the OS, so **infer from the tools available**, and default to the always-safe Web path:
- **Desktop path** — only if a **local-filesystem write tool / Desktop file access** is available (a filesystem MCP, or local file tools). Then you can write the project tree straight to a folder the user chooses.
- **Web path (default)** — the normal code-execution sandbox with no local FS: build the tree in the working directory and deliver **ZIP(s) + inline previews** via the file-presentation tool.
- **If unsure, ask once:** `Are you on Claude Desktop (I can save into a local folder) or the web app (I'll hand you a downloadable package)?`

Never assume local folder access exists — if you can't verify a local-write tool, use the Web path.

## 2) Standard project structure
Identical for both desktop folders and ZIP packages:

```text
Project Name/
├── Character Sheets/
├── Storyboards/
├── Production Images/
├── Thumbnails/
├── Video Prompts/
├── Generated Videos/
├── Reference Images/
└── Project Files/        # metadata, logs, manifest
```

Create folders on demand (the script's `scaffold` does this; it's idempotent). Only include categories the project actually uses, but the scaffold makes them all so the layout is predictable.

## 3) Smart naming convention
Consistent across **every** workflow and batch:

| Category | Pattern | Example |
|---|---|---|
| Character Sheets | `CharacterSheet_NNN.png` | `CharacterSheet_001.png` |
| Storyboards | `Storyboard_NNN.png` | `Storyboard_001.png` |
| Production Images | `Shot_NNN.png` | `Shot_001.png` |
| Thumbnails | `Thumbnail_NNN.png` | `Thumbnail_001.png` |
| Video Prompts | `VideoPrompt_NNN.txt` | `VideoPrompt_001.txt` |
| Generated Videos | `Video_NNN.mp4` | `Video_001.mp4` |
| Reference Images | `Reference_NNN.png` | `Reference_001.png` |

Use 3-digit zero-padded indices. Get the exact name from the script: `python scripts/project_export.py name "Production Images" 7 png` → `Shot_007.png`.

## 4) Prompt preservation (reproducibility)
**Every generated media asset stores its source prompt** as a matching `.txt` sibling in the same folder:
```text
Production Images/
├── Shot_001.png
├── Shot_001.txt        # the exact prompt that made Shot_001.png
├── Shot_002.png
└── Shot_002.txt
```
This guarantees any asset can be reproduced or iterated later. (`scripts/bulk_builder.py` already emits one `.txt` per prompt — rename/move them to match their asset, or generate the asset from that prompt and keep both.) The manifest links each asset to its `prompt_file`.

## 5) Project metadata files (in `Project Files/`)
Generated by `project_export.py package`:
- **`project_summary.md`** — human-readable: project name, created/packaged dates, models used, credits used, settings, asset counts per category.
- **`generation_log.md`** — workflow history (ordered steps) + prompt history.
- **`asset_manifest.json`** — machine-readable: models, credits, settings, totals, every asset with size + linked prompt file, prompt/workflow history.

Pass what you know via `--meta meta.json` (all keys optional):
```json
{
  "project_name": "Cyberpunk Detective",
  "created": "2026-06-08",
  "models": {"images": "Nano Banana Pro", "video": "Kling 3.0"},
  "credits_used": 2450,
  "settings": {"aspect_ratio": "16:9", "style": "neo-noir"},
  "prompt_history": [{"asset": "Shot_001.png", "prompt": "..."}],
  "workflow_history": ["Generated character sheet", "Generated 100 shots"],
  "notes": "..."
}
```
Track `credits_used` from the confirmation/`get_cost` step so the summary is accurate. These files let users reproduce or continue a project later.

## 6) Claude Desktop workflow
When a local-filesystem tool is available:
1. **Before generating, offer the destination:**
```text
Where would you like to save this project?
  📁 Choose a folder (tell me the path)
  🗂️ Use the default project folder
```
There's no GUI picker — "choose a folder" means the user gives a path. A sensible default is `~/Cinematic Prompt Studio/<Project Name>/`.
2. **Folder customization** — ask their preference: everything in one folder · categorized subfolders (default) · auto-create a new named project folder.
3. `scaffold` the tree at that path (creating folders as needed), write each asset with the naming convention + its prompt sibling, then `package` to drop the metadata files in `Project Files/` (and optionally a ZIP too).

## 7) Claude Web workflow (preview + downloadable package)
Default. Web users can't save to local folders, so deliver **two ways at once**:
1. **Direct preview in the conversation** — show generated images, storyboards, thumbnails, and asset previews inline so the user can review immediately.
2. **Downloadable project package** — assemble the tree in the working dir, `package` it into `ProjectName_Assets.zip` (assets + prompts + metadata + logs), and hand it over with the file-presentation tool.

Always show previews *and* provide the package — quick review plus professional hand-off.

## 8) Large-project handling (ZIP splitting)
For big runs (e.g. 100 storyboards, 500 images, 100 videos), `package` automatically splits when the total exceeds the size cap, **preserving the folder structure inside every part**:
```text
ProjectName_Part_01.zip
ProjectName_Part_02.zip
ProjectName_Part_03.zip
```
- Control the threshold: `--max-zip-mb 500` (default 500; `0` = never split).
- One part → `ProjectName_Assets.zip`; multiple → `..._Part_NN.zip`.
- Splitting is by whole files (bin-packed), so each asset stays intact and every part keeps `ProjectName/Category/...` paths. Present all parts together and tell the user how many there are.
- A single file larger than the cap goes in its own part (not span-split).

## 9) "Export Entire Project"
At any point the user can say **"export the project"**. Then:
1. Make sure every asset is in the right category folder with the correct name and its prompt sibling.
2. Update `--meta` (models, total credits used, settings, full prompt + workflow history).
3. Run `package` → metadata files + ZIP(s).
4. Desktop: confirm it's written to their folder. Web: present the ZIP(s) with a one-line summary (counts, credits, parts).

## 10) Honest platform limits
- **Folder colors / icons / tags / labels** are an OS-level nicety the skill **cannot set** (no Finder/Explorer control). Treat as optional and never depend on it. The only portable "visual" cue you control is putting an emoji in a folder *name* — offer that if the user wants it, but the standard names above are the default.
- On Web there is no persistent local folder; persistence is the downloaded ZIP. Encourage users to keep the ZIP (and its `Project Files/`) so they can re-import and continue later.
- Don't claim a file was saved locally unless a local-write tool actually returned success; otherwise deliver the ZIP.
